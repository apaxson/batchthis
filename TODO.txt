* DescriptiveQuantityField stores TEXT in a REAL column (Aaron, 2026-09-24 -
  needs resolving). It stores markup like "22.71:gallon" / "20:degree_Celsius",
  but it subclasses django-pint's QuantityField, whose get_internal_type() is
  FloatField, so the column is `real` (max_length=30 is ignored). SQLite
  accepts text there; PostgreSQL/MySQL would reject it. Affects Batch.size,
  Vessel.capacity/fill, BatchAddition.amount, BatchTest.value, Recipe
  batchSize/estFG, Yeast min/max temp, RecipeFermentable amount.
    * Fix before any move off SQLite: make the field a real text column
      (get_internal_type() -> "CharField" with max_length), then
      makemigrations - SQLite keeps the same text values, so existing
      rows survive. Also check the markup fits max_length (long float
      reprs like "20.000000000000004:degree_Fahrenheit" are 36 chars).
    * Related: set_base_units() changes self.base_units on the shared
      field instance per value (per-row state on a class-level object).

* Timezone-naive timestamps from the old signals (Aaron, 2026-09-24 - fix
  later). models.py addActivity (ActivityLog.datetime) and addGravityTest
  (the automatic starting-gravity BatchTest.datetime) use datetime.now(),
  which is naive, while everything newer uses timezone.now() (aware, UTC).
  Entries can sort/display inconsistently next to each other. Use
  timezone.now(); check existing rows. While there, decide whether to
  keep the "Batch Modified" ActivityLog line added on every batch save
  (transfer/complete/edit add it as noise next to the real entry).
